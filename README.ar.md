# School-Cover — دليل الاستخدام

[English / الرئيسية](README.md)

## عن المشروع

يساعد النظام مسؤول الاحتياط على تسجيل الغياب واقتراح البدلاء ومتابعة الاعتماد والتنفيذ وعدالة التوزيع. الاقتراح يحتاج مراجعة واعتماد المسؤول.

هذه حزمة عرض للنشر تضم 6 معلمين بأسماء تجريبية وشعبتين و10 حصص أسبوعية مصطنعة، ولا تضم جداول المدرسة الأصلية. احتفظ بنسخة المدرسة الحالية كما هي واختبر هذه النسخة في ملف جديد.

## الإعداد

1. أنشئ Google Sheet جديدًا، ثم افتح Extensions → Apps Script.
2. أنشئ ملفات Script باسم Core وStore وSeed، وملف HTML باسم Index، وانسخ محتوى الملفات المقابلة من src.
3. أظهر appsscript.json من إعدادات المشروع وانسخ محتوى ملف الإعداد المرفق.
4. أضف Google Sheets API v4 بالرمز Sheets من Services. عند استخدام مشروع Google Cloud قياسي، فعّل API فيه أيضًا. [مرجع Google](https://developers.google.com/apps-script/guides/services/advanced).
5. شغّل setupProject بحساب المالك وامنح الصلاحيات، ثم validateSetup. النتيجة المتوقعة: ok: true، teachers: 6، classes: 2، lessons: 10. لعرضها في السجل يمكن تشغيل دالة مساعدة تحتوي console.log(validateSetup()).
6. انشر Web app من Deploy → New deployment، وابدأ بتنفيذ Me ووصول Only myself. [دليل Google](https://developers.google.com/apps-script/guides/web).

تُضاف البيانات التجريبية مرة واحدة؛ تكرار setupProject لا يصفر السجلات ولا يستبدل التعديلات. GitHub لعرض الكود وحفظه، والتشغيل الفعلي في Google Apps Script.

## الحسابات المسموحة

يتحقق الخادم من هوية الحساب. أضف ALLOWED_EMAILS في Script properties بقائمة عناوين مفصولة بفواصل، تشمل المالك. جميع الحسابات المسموحة لها صلاحيات إدارية كاملة.

قد لا تتوفر هوية الزائر عند التنفيذ بحساب المالك. عند النشر لعدة مسؤولين يمكن اختيار التنفيذ بحساب المستخدم الزائر، مع منحهم صلاحية تعديل Google Sheet وإتمام التفويض. اختبر الوصول فعليًا بحسب إعدادات حسابك.

الخاصية OWNER_ONLY_BLANK_IDENTITY=true مخصصة فقط لنشر Only myself إذا تعذر ظهور هوية المالك؛ لا تستخدمها للنشر العام أو المتعدد المستخدمين.

## تجربة سريعة

اختر التاريخ 2026-09-13، وسجل غياب «معلم تجريبي 1» ليوم كامل. انتقل إلى توزيع الاحتياط واضغط اقتراح التوزيع. يفترض ظهور حصتين بحاجة إلى بديل؛ راجع المقترحات ثم اعتمد. أكد التنفيذ فقط بعد تنفيذ الحصة. البيانات التجريبية محددة بفصل سبتمبر–ديسمبر 2026.

## الاستخدام اليومي

1. سجل الغياب الكامل أو الجزئي من صفحة غياب المعلمين.
2. اختر التاريخ واقترح التوزيع، ثم راجع البدائل والحصص التي تحتاج معالجة.
3. اعتمد التوزيع. الاقتراح وحده لا يُحتسب تنفيذًا.
4. أكد التنفيذ بعد الحصة، أو سجل التغيير مع السبب.
5. اطبع توزيع اليوم وراجع صفحة العدالة والسجل.

## تحديث الجدول وإضافة معلم

أضف المعلم من البيانات والإعدادات، ثم حدد أهليته للمادة والصف. راجع تاريخ الانضمام والمشاركة والحد اليومي. يمكن تسجيل رصيد افتتاحي من الموازنة الإدارية بعد معاينة القيمة.

لتغيير الجدول، نزّل CSV من الواجهة، وعدّل معرّفات المعلمين والشعب والمواد مع الحفاظ على الأعمدة. أضف الكيانات الجديدة أولًا. ارفع الملف، وراجع الأخطاء، ثم اعتمد نسخة بتاريخ سريان صحيح. راجع التكليفات والغيابات المستقبلية المتأثرة. لا تحذف السجل القديم.

للغياب الطويل، سجل الغياب في الأيام الدراسية المعنية. قيد الإعفاء يمنع اختيار المعلم بديلًا، لكنه لا يغني عن تسجيل غيابه لإنشاء احتياج حصصه.

## الصيانة

استخدم الواجهة بدل التعديل اليدوي لخلايا التخزين، التي تحتوي قيمًا بترميز JSON. احتفظ بنسخة احتياطية قبل التحديثات الكبيرة. راجع الفصل والعطلات والقيود قبل التشغيل، وأضف فصلًا جديدًا بتواريخ غير متداخلة عند الحاجة.

هذه النسخة للنشر ببيانات تجريبية. لا تنقل Seed.gs التجريبي إلى نسخة المدرسة التشغيلية.
